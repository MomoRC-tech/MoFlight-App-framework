## Handoff correction, failures and limits

The first successful live save returned to a still-loading ordinary list. Immediately reopening options then produced a read-only recovery warning and disabled backup. The ordinary read queue had not covered the independent native flow. #40 adds a reservation before registry/candidate access, drains admitted readers and releases after teardown; later reads wait. Actual divergent/unreadable candidates still require recovery. Quiet restart and backup demonstrate preserved data, while the corrected-source trial reaches the enabled backup chooser without that warning. The final writable backup, independent manifest/record/receipt checks and offline restart confirm the scoped correction; #40 is complete for this Android handoff scope.

Retained failed attempts are explicitly excluded from whole-pass claims: initial APK path mismatch; loading-state captures corrected by ready/enabled waits; too-short live completion cutoff; the actual handoff defect; an ADB hierarchy-read timeout; and system-folder-picker readiness/cancellation assumptions (including a stopped caller returning to Launcher). The final helper checks fresh picker/app state explicitly, confirms the currently selected local device folder, and waits for native backup validation before readback. Only idempotent hierarchy reads receive bounded retries; mutation commands are not blindly replayed. Original display/network values and APKs were preserved/restored for the named earlier trials. Initial host issues (nullable accessibility prop, changed navigation expectations, an incomplete synthetic row, heading/body assertion and promise-executor lint) were corrected; Windows diagnostic output uses `PYTHONIOENCODING=utf-8` after the first cp1252 printing failure.

The journey is **automatic, not instantaneous**. One corrected-source emulator observation took **252.7 seconds** from the initiating action to the saved-result observation, including UI-harness feedback; it is not a performance benchmark. [#41](https://github.com/MomoRC-tech/MoFlight-App-framework/issues/41) records bounded timing investigation separately. #36 retains its original risk acceptance, without a new root-cause/fix claim.

Fresh credential entry on the actual provider page, native wrong/second account, spoken TalkBack, physical devices and iOS runtime remain untested here. Synthetic/host tests do not establish those gates.
