## Implementation

The native dated-window screen automatically chooses the current UTC calendar year and `Pilot oder Begleiter` using the freshly observed original controls. It validates every returned page against that requested date scope, follows only observed paging links, rereads profile context before each following page and after reading each page before committing it, and saves each success before continuing. An optional batch control keeps the provider preference by default, or selects 5/200 rows through its original same-origin POST configuration form and original Anwenden button. The app changes only the row-size select, rejects ambiguous controls and stops after one unsuccessful configuration attempt. Resume does not reconfigure saved pages. The saved summary includes page count. A first local association is confirmed once; saved matching context avoids repeated confirmations. It is a bounded lab, not lifetime-history retrieval.

The separate raw SQLite journal retains each page's URL, native observation timestamp, headers, values, DOM row IDs, optional actual detail links, date scope and record positions. Resume rereads the final committed page and requires unchanged evidence and context. Stale writes, changed counts/columns/scope, repeated rows, missing next links and context changes preserve earlier pages. Limits are 200 rows per page, 1,000 records or 100 pages; reaching a limit remains incomplete coverage.

List completeness, accessible detail-link count and detail gaps are separate. Explicit empty windows require matching scope and a declared empty result. Both stored source identity and flight-time basis remain unverified. Canonical imports and book writes stay synthetic-only; no costs or provider credentials are read by these readers.
