## Scope and meaning of “mandatory”

This reviews the implemented runtime verification families reached by ordinary combined Sync and its shared local admission, selection, recovery, save and readback paths, including the other-source jobs, advisory preview/status and Development hooks. Individual field assertions are grouped under their actual validator; this is not a claim to audit every assertion in unrelated AI/cloud/photo/book/financial-development flows or to delete development tests. Native backup/restore admission is reviewed where it blocks Sync; whole-archive import verification remains a separate operation.

“Contract-required” means necessary to an existing ownership, completeness, preservation or recovery property. It is not a claim that a law requires this exact algorithm or frequency. Full-history replay on every open, exact-schema comparisons at every read and repeated profile navigation are implementation choices, not immutable requirements. Any replacement still has to preserve the required property and show its actual benefit. Risk below describes deleting the check without a replacement.

No functional verification was found to be obsolete merely because it is old. In particular, old journals, uncertain commits and owner/selection fences are reachable recovery behavior. The removed cost is repeated execution of already-proven semantic validation, not silent weakening of those contracts. Adjacent gate consolidation, per-source profile batching, schema-check cadence and diagnostic reduction remain explicit follow-up candidates with unmeasured benefit and moderate or low feature-specific risk; they are not claimed implemented.

## Implemented increment and regression evidence

`SyncVerificationScope` retains one graph text and up to 128 exact command-row texts, each text pool capped at 4 Mi UTF-16 code units (about 16 MiB text maximum combined). It is created for one explicit update/connect admission, bound to owner/store/lease, and never serialized. Unknown/oversized graphs keep the original validate-before-serialize path. Every open still reads actual SQL content, schema and ownership/selection; identical graph/command bytes can reuse semantic proof. Changed content, even at the same generation, takes full validation. Current resolutions/pending outcomes are freshly checked. Initial and post-write validations, commit/readback and recovery remain. Closing/backgrounding/cancelling/finishing disables and clears reuse. A return from background safely falls back to ordinary validation.

Local recovery and date-window planning now remain in the preparation progress phase. Provider verification begins when the provider request is actually admitted. This changes phase boundaries; compare complete operations or the fixed benchmark, not old/new account-label durations as equivalent endpoints. No appearance, layout or navigation redesign is included. The Development comparison uses existing disclosure/action components and the existing busy gate.

Host checkpoints so far: 212 existing/focused library/journal/native/service/controller tests pass before the final additional lifecycle tests; the later 105 scope/controller and 107 scope/controller/Settings checks pass, types and changed-file lint pass. The new real-SQLite tests compare entire backups/receipts/results, changed same-generation records, schema damage, journal-hash corruption, newly pending/resolved commands, provider-wait mutation, foreign owner/lease, bounded eviction and lifecycle invalidation. Full graph validation at repository open drops from three calls to one in that fixed scenario; post-write validation uses its separate service span and remains. The benchmark contract passes ten identical synthetic trials with exact graph/receipt equality. These are host contract assertions, not a phone speedup or measured native improvement.

`sync-verification-benchmark.ts` supplies a paired native control/candidate comparison in one committed APK: control omits the proof scope, candidate uses it, both clone byte-identical populated closed seeds, alternate five pairs, use immediate synthetic provider results, independently export/read back the final graph and recover the pending journal outside the measured interval. Its endpoint includes local admission, entry recovery and automatic update/review/save/readback; excludes provider/network, actual owner-registry admission, UI presentation and clone/audit overhead.
