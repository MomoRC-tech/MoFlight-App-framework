## Keyboard-safe swipe repair — 29 October 2026

**#51 scope:** enforce the existing no-text-input boundary for generic controller gestures. Implemented in `40b1d8d`, refined against native Gboard evidence in **`9174b067e218b7a4c275a92be1f49f70e4fc53d5`**. This Python-only developer-tool change adds no application feature, dependency, model execution or service. Existing 720-second/40-action/8-capture ceilings, failed-action accounting, device/provenance/allowlist and cleanup controls remain.

Before each up/down swipe, freshly read native input-method state and admit only confirmed hidden state. Visible, pending, malformed, incomplete, contradictory or unavailable evidence emits no gesture. Keyboard inspection returns fixed allowlisted state flags, without surrounding editor diagnostics. Native Gboard retains `mIsInputViewShown=true` after dismissal: when window fields exist, admission requires `mInputShown=false`, both window booleans false, zero system IME window state and no pending show. The legacy no-window form requires both input/view flags false. Unknown formats remain refused. [Android's service source](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/core/java/android/inputmethodservice/InputMethodService.java) separates the cached input-view state from decor/window visibility; the current API37 observation below determines this bounded implementation, not a promise for every OEM/Android release.

**Verification:** four initial new regression methods fail on the unguarded baseline; two follow-up window-evidence methods fail on the first conservative candidate. Final **30/30 controller tests** and **144 Python tests (16 skipped)** pass. Coverage includes both directions, visible/pending/missing/malformed/conflicting/failed probes, the native dismissed-view shape, preserved bounded coordinates, fixed-field output, actual loopback HTTP, budget rejection and exact cleanup. Logs remain ignored under `build/ui-ime-20261029/` (`window-red.log`, `controller-green.log`, `python-tests-final.log`). No TypeScript/app build was needed for this Python-only change.

**Native guard acceptance:** reuse the installed, hash-verified committed-source `cc22902` Release on MoFlight_Synthetic_API37/emulator-5578, Android17/API37, dark/offline, 1080×1920px/420dpi = 411.43×731.43dp/font1.0. A deterministic parent probe used the actual controller and empty offline Help search, with no model worker. Both swipe directions were refused while Gboard was visible and the query stayed unchanged. After actual Back dismissal, the retained input-view flag stayed true but both windows were false/system state zero; both scroll directions then completed and the query remained unchanged. Returned to Start. **17 controller actions**, including the two expected refusals, **0 captures**, **0 cleanup errors**, 26.359s active controller time. This is bounded tool execution time, not a model/performance comparison. [Sanitized native result](assets/2026-10-18-ui-agent-experiment/controller/ime-guard-2026-10-29.json).

The initial navigation-only session was stopped cleanly to add the observed dynamic Profile label to the reviewed allowlist; no selector was bypassed. The first full probe safely rejected visible gestures but could not scroll after dismissal because the initial parser required the cached input-view flag false. That failed native assertion drove the window-state refinement; a subsequent read-only session was stopped without actions. Final evidence is the separate `issue51-ime-20261029-verified` session, not a relabelled earlier pass. All original logs/XML remain ignored under `build/ui-agent/issue51-ime-20261029*`.

Display/font, offline flags and installation identity compare exactly before/after; the app remains at Start and the initially running synthetic AVD remains running. No data clear/seed, profile save, real draft change, provider session access, Sync, model call, paid execution or APK replacement. No gesture was injected over the visible keyboard, independently of its typing mode; the Gboard glide-typing preference was not changed or inspected. This establishes the controller boundary on the recorded platform, not general physical/iOS UI acceptance or retroactive safety of older unguarded runs. No new APK is delivered; application source remains `cc22902`.
